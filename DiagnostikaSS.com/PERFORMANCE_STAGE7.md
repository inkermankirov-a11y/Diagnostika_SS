# Stage 7 — conservative database codec optimization

Retain localStorage key diagnostika-web-v1, schema 4, JSON fallback, DSS15V1 prefix, header, exact checksum algorithm, validation and atomic replacement semantics. No migration to IndexedDB, no deletion or relocation of data, no file changes, no database copies, no additional writes. The codec now packs through a bounded typed-array chunk and computes FNV-1a while packing/unpacking instead of traversing bytes a second time. Stored size is unchanged. Performance claims depend on measurements.

Tests cover exact packed string equality with original version, cross-read in both directions, Unicode and boundary lengths, synthetic photos and attachment references, 100 clients, unknown fields, malformed input, quota failure, legacy JSON fallback and comparative CPU measurements. Client attachment binaries remain managed by unchanged file storage; this is not a complete attachment-store audit. Database.js, synchronization, permissions and backup behavior unchanged. No IndexedDB migration: that would alter a sensitive synchronous contract and require separate recovery and compatibility work. No production deployment.
