# Diagnostika SS — два отдельных сайта

В проекте оставлены **ровно два самостоятельных экземпляра веб-приложения**:

- [DiagnostikaSS.com](DiagnostikaSS.com/) — первый (основной) сайт.
- [DiagnostikaSS.ru](DiagnostikaSS.ru/) — второй сайт.

Каждая папка содержит собственный `index.html`, стили, скрипты, модули и остальные файлы. Изменения в одном экземпляре не затрагивают другой.

## Адреса сайтов на GitHub Pages

- [Основной сайт .com](https://inkermankirov-a11y.github.io/Diagnostika_SS/DiagnostikaSS.com/)
- [Второй сайт .ru](https://inkermankirov-a11y.github.io/Diagnostika_SS/DiagnostikaSS.ru/)

Исходный адрес `https://inkermankirov-a11y.github.io/Diagnostika_SS/` автоматически перенаправляет на первый сайт.

**Важно:** названия папок `.com` и `.ru` — не означает, что собственные домены уже зарегистрированы и настроены. Пока оба экземпляра размещаются как отдельные пути на GitHub Pages.

## Структура репозитория

- `DiagnostikaSS.com/` — все файлы первого сайта.
- `DiagnostikaSS.ru/` — все файлы второго сайта.
- `.github/workflows/` — служебные автоматические проверки, публикация и обновление погоды.
- `index.html` — переадресация с прежнего адреса.
- `.nojekyll` — файл настройки GitHub Pages.
- `.gitignore` и `README.md` — служебные файлы проекта.

Старый третий комплект файлов из корня удалён. Проверки GitHub Actions работают из каталога первого сайта. Обновление погоды применяется к обеим версиям.

## Данные и интеграции

Исходные клиентские данные не копировались в репозиторий. Первая версия сохраняет прежние браузерные ключи, у второй ключи изолированы. Для полной независимости Google Drive, n8n, облачных БД и авторизации нужно отдельно настроить их на двух экземплярах. Храните персональные данные клиентов вне публичного репозитория.
